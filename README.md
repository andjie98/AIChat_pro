# AIChat_pro 1.2.0

当前工程是 AIChat_pro 的维护修复版，目标保持 Spigot/Paper 1.12.2、Java 8 运行环境。插件名称仍为 AIChat_pro，继续读取同一个插件数据目录。源码源自反编译恢复，已修复源码审查发现的 9 项问题。

## 构建与测试

使用 **JDK 17、Maven 3.9**（本次验证环境）执行：

```powershell
mvn -B -ntp clean verify
```

已缓存完整依赖时可加 `-o` 离线构建。产物为 `target/AIChat_pro-1.2.0.jar`。`--release 8` 保证生产 class 为 Java 8 字节码；测试使用 JUnit 4.13.2 和 Mockito 4.11.0，均不打入插件包。

## 云界资料库

首次启动时，插件会把内置的 61 条问答写到 plugins/AIChat_pro/guide.md。已有 guide.md 会保留，想用本版资料时可手动更新该文件。编辑后执行 /aichat reload。可在 config.yml 加 guide.enabled: false 关闭检索（嵌套 YAML 写作 guide: 下的 enabled: false）。

使用 UTF-8，每节以二级标题开头。可在节内写一行“别名：问法一、问法二”。本地检索遍历全部章节。唯一命中时私发原文和来源，不调用模型、不扣每日次数，仍受冷却限制。命中多个候选时最多传 3 条给模型，未配置 API 时私发匹配资料。明确的服务器问题未命中时提示暂未收录。随机搭话不检索指南。
 
## 上一版修复

1. 在同一把锁内检查冷却和额度，并建立请求预占；每位玩家最多一个未完成请求。只有成功才扣次数，失败/拒绝/排队超时/取消释放预占。跨日完成的请求不扣新一天的额度。
2. AI 请求使用有界队列，默认等待容量 32、排队超时 30 秒；执行线程仍由 api.max-concurrent-requests 控制。队列满返回明确提示。排队超时在任务取出执行前判断，不发出 HTTP 请求。
3. 修正 JSON 控制字符十六进制转义的参数类型。
4. 将成功回调移出 HTTP 重试边界；回调失败只记录错误，不重新请求 AI。每个请求只交付一次终态，正常回调在服务器主线程执行。
5. 保存统计采用修改版本号和串行写入，快照后的更新不会被错误标为已保存；通过临时文件加替换写入 data.yml。写入失败保持待保存状态。
6. 手动总结接入冷却、请求预占和每日额度；成功将 token 统计归属发起玩家。控制台不扣玩家额度，但仍受全服冷却和队列限制。
7. context.chat-lines=0 时不附带全服聊天上下文；MessageStore.last(0) 返回空列表。
8. 自动总结按消息序号记录成功处理位置，没有足够新消息则跳过；同一时间最多一个自动总结。失败不推进位置，以便以后重试。重载保留当前 SummaryService 的位置；完整重启时聊天缓存也会重建。
9. /aichat usage 在读取和发送统计前检查权限。

聊天事件只采集消息后转交主线程，玩家状态/权限检查和准入在主线程进行；HTTP 仍在专用工作线程执行。

## 新增配置

```yaml
api:
  max-queued-requests: 32
  queue-timeout-seconds: 30
```

已有 config.yml 不需要删除：缺少这两项时自动使用上述默认值。成功次数以外，失败请求仍保留已触发的短暂冷却，避免持续刷接口。额度预占不写入 data.yml，因为进程重启后排队中的请求也不会继续执行。

## 验证范围

`clean verify` 已通过 22 项回归测试，0 失败、0 错误、0 跳过。包括 32 种控制字符、实际问答上下文构造、并发请求预占、额度回收、冷却、保存期间发生新更新、磁盘写入失败、命令权限、手动总结记账、自动总结位置、队列容量/超时/取消、成功回调抛异常，以及本地 HTTP 401。

HTTP 测试只访问 127.0.0.1 上的测试服务，不使用真实 API 密钥或付费接口。Bukkit 使用模拟对象；尚未在真实 Minecraft 服务器验证加载、聊天事件和 PlaceholderAPI 集成。构建仍有旧 API 和反编译泛型警告。

## 安装

停服后备份现有插件与数据，将旧 AIChat_pro JAR 替换为本次修复版，避免两个同名插件同时存在；保留原有 config.yml、data.yml，然后启动服务器。版本显示为 1.2.0。
